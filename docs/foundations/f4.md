# F4 · 프로그램은 언제 도는가, 고장은 어떻게 고치나

<span class="chip chip--f">[기초 F4]</span> **4일차** · 4.3.3 안 8분(F4-a 실행 방식) + 8교시 4.3.6 15분(F4-b 디버깅 · Git ②)

!!! abstract "한 줄"
    조기 경보는 누가 버튼을 눌러야 도는 프로그램이 아니라, **정해진 시각에 돌며 조건을 보는 프로그램**입니다.
    그리고 고장은 **넣은 것 · 기대한 결과 · 실제 결과 · 재현 절차** 네 가지를 적으면 절반은 고친 것입니다.

!!! quote "계획서 근거"
    강의 세부 내용 "위험 스코어 및 연체 일수 기준치 초과 시 담당자에게 알림을 송출하는 금융 위험 조기 경보 로직 학습" ·
    실습 목표 "…데이터 연동 오류를 디버깅하고 최종 검증하는 최적화 능력 확보"

## 1. 비유 — 일하는 방식 네 가지, 그리고 병원 진료 {#analogy}

| 프로그램이 도는 방식 | 업무 비유 | 예 |
|---|---|---|
| **한 번 실행** | 필요할 때 계산기를 두드림 | 엑셀 계산, 노트북 '모두 실행' |
| **주기 실행**(스케줄 · cron) | 매주 월요일 9시 정기 보고 | "평일 09:00에 연체 목록을 새로 만든다" |
| **조건 실행**(트리거 · 웹훅) | 연기가 나면 울리는 화재경보기 | "새 인보이스가 들어오면 등급을 다시 계산한다" |
| **상시 실행**(서버) | 24시간 문을 연 편의점 | 대시보드 앱, 챗봇 |

→ 조기 경보 = **주기 실행 + 조건**. 매일 정해진 시각에 돌면서, 기준치를 넘은 바이어만 알립니다.

**디버깅 = 병원 진료.** "아파요"만으로는 의사가 고칠 수 없습니다. 무엇을 먹었고(**넣은 것**), 평소에는 어땠고(**기대한 결과**),
지금은 어떤지(**실제 결과**), 언제 그런지(**재현 절차**)를 말해야 합니다. AI에게 오류를 물을 때도 똑같습니다.

## 3. 용어 {#terms}

| 용어 카드 | 한 줄 정의 |
|---|---|
| 용어 4-7 **배치 · 스케줄(cron) · 이벤트 트리거** | 모아서 한 번에 처리 · 정해진 시각마다 자동 실행 · 어떤 일이 생기면 바로 실행 |
| 용어 4-12 **로그 · 디버깅(재현 절차)** | 언제 · 무엇을 · 결과를 남긴 기록 · 오류의 원인을 찾아 고치는 일(오류를 다시 일으키는 순서부터) |
| 용어 4-13 **브랜치 · 이슈** | 원본을 건드리지 않고 실험하는 사본 갈래 · 버그와 할 일을 적고 담당·상태를 추적하는 게시물 |

알아 둘 것

- **로그 = 언제 · 무엇을 · 결과.** 경보가 오지 않았을 때 '안 돌았는지, 돌았는데 조건에 안 걸렸는지'를 로그로 가립니다.
- **오류 메시지는 마지막 줄부터** 읽습니다. 오류의 종류와 한 줄 설명이 대개 맨 아래에 있습니다.
- **고치기 전에 기대값부터** 적습니다. 예: 시나리오가 심할수록 기대손실이 커져야 한다(S0 < S1 < … < S4). 이 순서가 깨지면 어딘가 틀린 것입니다.
- **AI가 고친 곳은 diff로 확인**합니다. "다 고쳤어요"라는 말보다 바뀐 줄이 정확합니다.

## 5. 익명 실패 사례 {#case}

<span class="chip chip--field">[현장 사례 · 익명]</span> **"조용한 실패"**

AI가 루브릭으로 점수를 매기는 한 평가 시스템은, 검증이 실패하거나 AI의 답을 읽어 내지 못하면 **보통 점수를 주고 통과**시키도록 짜여 있었습니다.
실패한 건도 결과표에서는 평범한 점수처럼 보였고, 무엇이 실패했는지 겉으로 드러나지 않았습니다.

**교훈** — 실패는 결과 속에 숨기지 말고 드러냅니다. 실패는 '실패'로 표시하고 로그에 남기며, 기대값과 대조해 찾아냅니다.
