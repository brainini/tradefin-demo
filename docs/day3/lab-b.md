## Step 5 예측 내보내기 {#step5}

**15:05–15:15 (10분)** · 보정 모델로 바이어 150곳의 30일 연체 확률(0–100%)을 내보낸다

=== "🟢 Basic"

    1. 캔버스 아래쪽 **File** ②를 더블클릭 → 폴더 아이콘 → `D3/d3_start_scoring.csv`(150행, 기준일 2026-09-30, 라벨 없음).
    2. 역할을 File ①과 같게 맞춥니다: `buyer_id` · `ref_date` · `sample_weight` · `split_suggested` = meta(있는 열만), `fx_krw_close` · `usd_krw_close` = skip → **Apply**.

        - 확률 열이 안 보이면 Predictions 위쪽 **Show probabilities for**를 **Classes known to the model**로 바꿉니다 — 라벨 없는 점수화 파일은 기본값으로는 확률 열이 나오지 않습니다(강사가 준 `d3_orange_model.ows`에는 이미 저장돼 있습니다).

        - 저장된 `d3_predictions.xlsx`의 **첫 열은 `Selected`**(Predictions가 붙인 열)입니다 — 그대로 둡니다.

    !!! note "이 확률은 '운영 연습용'입니다"
        예측 대상 150곳은 학습 파일에 들어 있던 같은 바이어들이라 확률이 낙관적일 수 있습니다. 모델의 성능은 **블록 A의 Test and Score(시험셋) 숫자로만** 말합니다.

## Step 6 S/A/B/C 등급 매칭 {#step6}

**15:15–15:45 (30분)** · t/4 · t/2 · t 밴드로 등급을 매기고, 등급별 실제 연체율이 순서대로 오르는지(단조성) 본다

!!! info "등급 규칙 — C부터 검사합니다"
    `C ≥ t` · `B ≥ t/2` · `A ≥ t/4` · 나머지 `S`(t = 블록 A Step 4에서 **보정된 확률 척도**로 정한 비용 임계값 — 이론값 1/6 ≈ 0.17 또는 🔵 비용표의 최소 구간. Calibration Plot 지표 그래프의 세로선 위치는 보정 전 척도라 여기에 넣지 않습니다). 등급 → 결제조건은 [교육용 가정]: S · A는 O/A 유지 · B는 결제기간 단축 · 부보 검토 · C는 선수금 · L/C만. 회사 내부 관리 등급이며 K-SURE 공식 등급이 아닙니다.

=== "🟢 Basic"

    **① 표 `pred` · 이름 `t`**

    1. `d3_predictions.xlsx`를 열고(노란 띠면 **편집 사용**) **A2** 클릭 → ++ctrl+t++ → **머리글 포함** → **확인** → **테이블 디자인** → 표 이름 `pred`.
        - `d3_grade_banding.xlsx`(파일 받기 표)를 쓰면 더 빠릅니다 — `기준` 시트 **B3**(노란 칸, 이름 `t`)에 t를 넣으면 경계값 **C6:C8**(t · t/2 · t/4)과 등급 분포 **B12:B16**이 저절로 계산되고, `pred` 시트 **A열**에 `buyer_id`, **C열** `pd_30d`에 연체 확률(이름 끝 `(1)` 열)을 값 붙여넣기 하면 **D열** `grade`(IFS, C부터 검사) · `threshold_used` · `model_version` · `approval` 열이 채워집니다. 단조성은 `단조성` 시트 **A–C열**(시험셋 `buyer_id` · 확률 · `late_30d`) → **F–I열** 등급별 실제 연체율, 저장은 `csv_6열` 시트에서 CSV UTF-8로(`00_사용법` 시트 참조).
    2. 연체 확률 열(이름 끝이 `(1)`인 열, 0–1 사이 값)의 머리글 칸을 클릭해 `pd_30d`로 바꿉니다.
    3. 표 오른쪽 빈 칸(예: 맨 위 빈 열의 1행)에 블록 A의 **t 값**(보정 척도 — 이론값 0.17 또는 🔵 비용표의 값)을 입력하고, 그 칸을 클릭한 채 **이름 상자**에 `t` → ++enter++ 로 이름을 정의합니다(`d3_grade_banding.xlsx`에서는 `기준`!B3이 이미 이름 `t`). 확률 열은 보정 모델의 값(`Gradient Boosting, calibrated (1)`)이어야 합니다 — 보정 전 그래프에서 읽은 t를 보정 확률에 대면 척도가 달라 등급이 한쪽으로 쏠립니다.

    **② 등급 수식 한 번 → 150곳 자동 매칭**

    4. 표 오른쪽 빈 열 1행에 `grade`, 2행에 아래 수식을 넣습니다. 표 안이라 150행에 저절로 채워집니다(표 밖이면 칸 오른쪽 아래 **채우기 핸들**을 끌어 내리거나 더블클릭).

        ```text
        =IFS([@pd_30d]>=t,"C",[@pd_30d]>=t/2,"B",[@pd_30d]>=t/4,"A",TRUE,"S")
        ```

        IFS가 없는 엑셀(2016 이하)은 같은 뜻의 중첩 IF를 씁니다.

        ```text
        =IF([@pd_30d]>=t,"C",IF([@pd_30d]>=t/2,"B",IF([@pd_30d]>=t/4,"A","S")))
        ```

    5. 열 세 개를 더합니다: `threshold_used` = `=t` · `model_version` = `orange_xgb_sigmoid`(글자 그대로) · `ref_date` = `2026-09-30`(칸 서식 **yyyy-mm-dd**).
    6. 열 하나 더: `approval` = `=IF([@grade]="C","승인 필요","")` — 등급은 모델이 제안하고, C등급의 조건 변경은 사람이 승인합니다(이 열은 CSV에는 넣지 않습니다).

    **③ 정렬 · 필터 · 조건부 서식 — 등급별로 묶어 보기**

    7. `pd_30d` ▼ → **숫자 내림차순 정렬**. 위쪽이 C등급입니다.
    8. `grade` 열을 선택 → **홈** → **조건부 서식** → **셀 강조 규칙** → **텍스트 포함** → `C` 빨강 · 같은 방법으로 `B` 주황. 색만이 아니라 글자로도 등급이 보입니다.
    9. **삽입** → **피벗 테이블** → 새 워크시트 → 행 `grade` · 값 `buyer_id`(개수) → 등급 분포를 `d3_work`의 `03_등급`에 옮깁니다.

    **④ 단조성 — 등급이 높을수록 실제 연체율이 높은가**

    10. 예측 대상 150곳에는 정답이 없으니, **정답이 있는 시험셋**으로 같은 밴딩을 해 봅니다. Orange에서 **Predictions**를 하나 더 놓고 Data = **Remaining Data**, Predictors = Calibration Plot 출력 모델 → **Save Data** → `D3/d3_test_pred.xlsx`(🔵 Step 4에서 만들었으면 그대로).
    11. `d3_test_pred.xlsx`에서 같은 순서(표 → `pd_30d` → 이름 `t` → `grade`)로 등급을 매기고, 피벗: 행 `grade` · 값 `late_30d`(**평균** — 값 필드 설정 → 평균) = 등급별 실제 연체율.
    12. `03_등급`에 표를 옮기고 **S < A < B < C** 순서로 오르는지 봅니다. A · B는 행이 몇 개뿐이라 들쭉날쭉할 수 있습니다 — 그래도 C가 S보다 낮게 나오면 t와 수식 순서를 다시 봅니다.

    **⑤ 6열 CSV 저장 — 분류 모델 결과물**

    13. `pred` 표에서 `buyer_id` · `ref_date` · `pd_30d` · `grade` · `threshold_used` · `model_version` 6열의 **열 머리 글자**를 ++ctrl++ 를 누른 채 클릭 → ++ctrl+c++ → 새 시트 **A1** → 마우스 오른쪽 → **값(V)** 붙여넣기. 열 순서가 위와 같은지 봅니다(다르면 열을 잘라 붙여 순서를 맞춥니다).
    14. 그 시트를 연 채 **파일** → **다른 이름으로 저장** → `d3_end_scored__T조-번호` → **CSV UTF-8(쉼표로 분리)** → **저장** → 여러 시트 안내에 **확인**. 닫을 때는 **저장 안 함**.
    15. 메모장으로 열어 첫 줄이 `buyer_id,ref_date,pd_30d,grade,threshold_used,model_version`이고 줄 수가 151인지 확인합니다.

=== "🔵 Standard"

    **분위수 컷과 비교 — 엇갈린 바이어 토론**

    1. `pred` 표에 `pct` = `=PERCENTRANK.INC(pred[pd_30d],[@pd_30d])`와 `grade_q` = `=IFS([@pct]>=0.85,"C",[@pct]>=0.5,"B",[@pct]>=0.15,"A",TRUE,"S")`를 더합니다(상위 15%를 C로 — 비율로 자르는 방식).
    2. `grade`와 `grade_q`가 다른 바이어를 필터로 모아 몇 곳인지 `03_등급`에 적습니다.
    3. 짝과 3분 토론합니다: **"비용으로 자르는 등급과 비율로 자르는 등급 중, 내 회사의 한도 회의에는 어느 쪽이 설명하기 쉬운가?"** 결론 한 줄.
    4. 내 회사의 결제조건으로 '등급 → 행동표'(S · A · B · C마다 결제조건 · 한도 · 부보)를 한 줄씩 씁니다 — 6일차 개인 기획서 6장의 재료입니다.

=== "🟣 Challenge"

    **등급 함수 + 단조성 표**

    1. 등급 규칙을 함수로 만듭니다: `def grade(p, t): return "C" if p >= t else "B" if p >= t/2 else "A" if p >= t/4 else "S"`.
    2. out-of-fold 점수(Step 5 🟣)에 적용해 등급별 실제 연체율 · 행 수 표를 만들고, 단조성이 깨지는 곳이 있는지 봅니다.
    3. `d3_end_scored_challenge.csv`로 저장해 Basic 결과와 등급이 다른 바이어 수를 셉니다.

## Step 7 SHAP 해석서 {#step7}

=== "🟢 Basic"

    **① 전역 설명 — Explain Model**

    1. **Explain Model**을 더블클릭 → **Target class** `1` → 상위 10개 특성 그림을 캡처합니다(++win+shift+s++). 빨강 점 = 그 특성 값이 큰 바이어, 오른쪽 = 연체 위험을 올림.
    2. 오른쪽(위험↑)으로 빨강 점이 많이 퍼진 특성 3개를 메모합니다. 재무비율보다 결제 행동 특성이 위에 오는지도 봅니다.

    **② 개별 설명 — C등급 1곳**

    3. Step 6의 `pred` 표에서 C등급 바이어 한 곳을 고릅니다.
    4. Orange의 Predictions 뒤 **Data Table**에서 그 `buyer_id` 행을 클릭합니다 → **Explain Prediction**을 엽니다.
    5. **기준값**(전체 평균 위험) · **이 바이어의 예측** · 특성별 막대(빨강 = 위험↑, 파랑 = 위험↓)를 캡처하고, 기여가 큰 순서로 5개를 표로 옮깁니다: **특성 │ 이 바이어의 값 │ 기여(+ 위험↑ / − 위험↓)**.

    **③ P3-1 — 숫자만 넣어 해석서 초안**

    6. AI 화면에서 **새 채팅**을 열고 **P3-1**을 붙여 넣습니다. `[입력]`에 buyer_id · `pd_30d` · 등급 · t · 기준값 · 전역 상위 8개 이름 · ②의 기여 표 · 특성 한글명(모르면 열 이름 그대로)을 넣어 보냅니다. **데이터 파일은 올리지 않습니다.**

    **④ `d3_shap_memo` — 사람이 고쳐서 완성**

## Step 8 환율 위험 구간 + 금요일 저장 {#step8}

**16:25–16:45 (20분) + 16:45 저장 확인** · 같은 원/달러 데이터로 예측 구간을 그리고 '6월 초 급등이 구간 안이었나'를 판단한다

!!! info "오늘의 질문 하나"
    `fx_forecast_inputs.csv`는 원/달러 일별 종가(FRED DEXKOUS)이고, `split` 열이 `train`(~2026-05-29)과 `valid`(2026-06-01~09-25)로 나뉘어 있습니다. **train으로만 예측 구간을 그린 뒤, valid 기간의 실제값 — 특히 6월 초의 급등 — 이 95% 구간 안에 들어왔는지** 봅니다.

=== "🟢 Basic"

    **엑셀 예측 시트(ETS) — 주평균으로**

    1. `fx_forecast_inputs.csv`를 엑셀로 엽니다(열: `date` · `usd_krw` · `split` · `source`).
    2. E1에 `week`, E2에 `=A2-WEEKDAY(A2,2)+1`(그 주의 월요일)을 넣고 끝까지 채웁니다. 영업일 자료를 주 단위로 묶어야 예측 시트가 '타임라인 간격' 오류를 내지 않습니다.
    3. **삽입** → **피벗 테이블** → 행 `week` · 값 `usd_krw`(**평균**) · 필터 `split` = **train** → 피벗 결과(주 · 평균 두 열)를 복사해 새 시트에 **값(V)**으로 붙입니다.
    4. 두 열을 선택 → **데이터** → **예측 시트** → 선형 차트 → **옵션**: 예측 종료 `2026-09-21` · 신뢰 구간 `95%` · 계절성 **자동 검색** · 누락된 요소 채우기 **보간** · 중복 집계 **평균** → **만들기**.
    5. 피벗 필터를 `split` = **valid**로 바꿔 확인 구간의 주평균을 구하고, 예측 시트 표 옆에 같은 주끼리 붙입니다.
    6. 주마다 `=AND(실제>=하한,실제<=상한)`으로 구간 안인지 표시하고, **구간 안에 든 주 수 / 전체 주 수**와 **6월 첫 주(2026-06-01 주)**의 판정을 `d3_work`의 `04_환율`에 적습니다.
    7. 한 줄 해석을 씁니다: 예측 구간이 무엇을 담았고 무엇을 놓쳤나 → **"예측은 시나리오의 폭을 정하는 데 쓰고, 헤지 시점을 맞히는 데 쓰지 않는다"** — 4일차 환율 충격 시나리오로 이어집니다.

    !!! warning "16:45 금요일 저장 확인 — 세 곳에"
        `d3_end_scored__T조-번호.csv`를 **① 내 PC `D3` 폴더 ② 내 Google Drive ③ 제출 폼**에 둡니다. 헬퍼가 자리마다 확인합니다. `d3_work` · `d3_shap_memo`도 함께 저장합니다(++ctrl+s++).

=== "🔵 Standard"

    **Orange ARIMA(1,1,1) + MAPE**

    1. 새 **File** → `fx_forecast_inputs.csv` → **Select Rows**(`split` **is** `train`) → **As Timeseries**(시간 변수 = `date`).
    2. **ARIMA** 위젯: p `1` · d `1` · q `1` [교육용 가정] · 예측 단계 `82`(valid 행 수) · 신뢰 구간 `95%` → **Line Chart**로 원계열과 예측 구간을 봅니다.
    3. **Model Evaluation**으로 MAPE를 보고, valid 실제값이 구간 안에 든 비율과 6월 초 급등의 판정을 `04_환율`에 엑셀 결과와 나란히 적습니다.

=== "🟣 Challenge"

    **Colab Prophet — coverage · MAPE**

    1. `d3_challenge.ipynb`의 Prophet 절: train만으로 `Prophet(interval_width=0.95, daily_seasonality=False)`를 학습하고 valid 기간을 예측합니다.

    3. 세 경로 모두 같은 데이터인데 구간 폭이 왜 다른지(모델 가정) 주석으로 한 줄.

## 흔한 오류와 해결 {#troubleshooting}

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | 모든 바이어가 S(또는 C) 한 등급 | IFS 검사 순서가 반대(S부터) · 이름 `t`가 정의되지 않았다 | C부터 검사하는 수식 그대로 · **수식** → **이름 관리자**에서 `t` 확인 |
| 2 | 등급 수식이 **#NAME?** | IFS가 없는 엑셀이거나 `t` 이름 오타 | 중첩 IF 수식으로 바꾸기 · 이름 상자에서 `t` 다시 정의 |
| 3 | `pd_30d`가 0–100으로 보인다 | 칸 서식이 백분율이거나 다른 열을 골랐다 | 확률 열(이름 끝 `(1)`)의 값이 0–1인지 확인. 백분율 서식이면 값은 그대로 둡니다 |
| 4 | 확률이 전반적으로 높다 | Predictions에 보정 전 모델(Gradient Boosting)을 연결했거나, Calibration Plot을 지표 그래프에 둔 채 넘겼다 | Predictors = **Calibration Plot의 출력 모델** — **Metrics**를 **Calibration curve**로 되돌린 뒤 다시 확인 |
| 5 | 단조성이 뒤집힌다(C 연체율 < A) | 시험셋 A · B 행이 몇 개뿐 · 또는 t가 잘못 들어갔다 | 행 수를 함께 적고 해석합니다. C < S면 t와 수식부터 확인 |
| 6 | Explain Prediction이 비어 있다 | Data Table에서 행을 고르지 않았거나 연결이 다르다 | Predictions 뒤 Data Table에서 한 행 클릭 → 연결선이 Selected Data인지 확인 |
| 7 | Explain 위젯이 오래 걸린다 | 배경 데이터가 크다 | 잠시 기다리거나 Data Sampler로 배경 100행 |
| 8 | AI 해석서에 입력에 없는 숫자 · 회사 정보가 있다 | AI가 그럴듯하게 채웠다 | 지우고 `입력에 없는 숫자와 사실은 지워라. 기여 부호는 바꾸지 마라.` |
| 9 | 예측 시트가 '타임라인 간격이 일정하지 않음' 오류 | 영업일(주말 · 휴일 빈칸) 자료를 그대로 넣었다 | 주평균으로 바꾼 뒤(Step 8 ②–③) 실행 |
| 10 | `week` 수식이 날짜가 아니라 숫자로 보인다 | 칸 서식이 일반 | 칸 서식 **날짜**로 바꾸기 |
| 11 | CSV 첫 줄에 `(1)`이 붙은 열 이름이 있다 | 머리글을 `pd_30d`로 바꾸지 않았다 | 표 머리글을 고친 뒤 다시 저장 |

더 많은 증상은 [FAQ·트러블슈팅](../faq.md)에 있습니다.
