## 2.3.1 금융 정형 데이터 전처리 실무 {#m231}

1교시 · #07–#14 · 용어 카드 2-1 · 2-2 · 2-3 · 2-4 · 띠: 이상치 · 중복

- **좋은 데이터는 네 가지를 갖췄습니다** — ① 설계된 데이터(무엇을 예측할지 먼저 정하고 모았다) ② 정형 포맷(한 칸에 값 하나, 한 열에 단위 하나) ③ 맥락·연결성(다른 표와 이을 키와 기준일이 있다) ④ 양과 다양성. <span class="chip chip--public">[공개 사례 · RAND 2024]</span> RAND가 정리한 AI 프로젝트 실패의 근본 원인 다섯 가지 중 둘이 데이터입니다 — 학습할 데이터 부족, 데이터를 관리·배포할 인프라 부족.
- **오염은 유형마다 규칙 하나로 고칩니다.** 오늘 표에는 여섯 유형이 있습니다 — 통화 표기 혼재 · 숫자 칸의 문자 · 단위 의심(자릿수) · 재무 항목 결측 · 자본잠식(음수 자본) · 국가위험 미분류('-'). 셀을 하나씩 고치지 않고, 유형마다 규칙 한 줄과 '왜'를 먼저 씁니다.
- **결측은 채우되, 비어 있었다는 사실도 남깁니다.** 재무 항목이 빈 바이어는 국가위험이 높은 쪽에 몰려 있습니다 — 그냥 채우면 위험한 바이어가 평범해 보입니다. 그래서 재무비율 4종은 같은 기준일 바이어들의 **중앙값**으로 채우고 `fin_missing` 표시를 함께 남깁니다(비교: 가장 닮은 바이어 값으로 채우는 1-NN). **스케일링**(Min-Max · Standard)은 오늘 비교만 하고 파일에 저장하지 않습니다 — 내일 모델 평가 안에서 학습 데이터 기준으로만 계산해야 시험 데이터 정보가 섞이지 않습니다(누수).
- **환율은 '기준일 또는 직전 영업일' 값을 붙입니다(as-of).** 기준일이 토요일이면 금요일 값, 기준일 뒤의 값은 쓰지 않습니다. 엔화 열은 100엔당 원이라 100으로 나눕니다. 환율 출처는 하나로 고정해 파일에 적습니다 — 오늘 파일은 미국 영업일 기준(FRED H.10 원화 교차환율)이라 미국 휴일은 빈칸입니다.
- **변환했으면 검산합니다** — 원본 합계와 행 수가 맞기 전에는 결과가 아닙니다. 검산 3줄: 행 수 · 통화별 건수 합 · 엔화 바이어 1곳 손계산. <span class="chip chip--field">[현장 사례 · 익명]</span> 주간보고 자동화에서 변환 뒤 합계 대조를 규칙으로 두었습니다.

| 하는 일 | 엑셀·구글 시트 | 메모 |
|---|---|---|
| 기준일 환율(as-of) | `=XLOOKUP(AsOf, fx[date], fx[usd_krw], , -1)` | −1 = 같은 날짜가 없으면 직전 값 |
| USD 환산 | USD 금액 = 원통화 금액 × (원/원통화) ÷ (원/USD) | 예: EUR 잔액은 × 원/EUR ÷ 원/USD — 결과는 Step 3에서 직접 |
| 엔화 | `jpy100_krw ÷ 100` | 안 나누면 100배가 된다 |
| 결측 대체(시트만 쓸 때) | `=MEDIAN(…)`으로 중앙값을 구한 뒤 `=IF(ISBLANK(x), 중앙값, x)` | Orange Impute에는 중앙값 메뉴가 없다 → Fixed value에 입력 |

## 2.3.2 정형·비정형 융합 특성공학 {#m232}

2교시 · #16–#18 · 용어 카드 2-5 · 2-6 · 띠: 재현 가능한 파이프라인

- **모델은 열만 읽습니다.** 특성 = 원천 데이터 + 도메인 규칙 + 기준일 — 예: 12개월 인보이스 → 연체 인보이스 비율(`late_ratio`), 최근 3개월과 직전 3개월 → 연체 추세(`dpd_trend`). "열이 많을수록 좋다"는 오해입니다 — 기준일 뒤 정보가 섞인 열 하나가 모델 전체를 속입니다(누수).
- **같은 바이어, 세 가지 모양**: 매출채권 표(정형) + 기사 한 줄(비정형) → AI가 낸 점수 JSON(반정형) → 바이어 한 줄의 열(정형). CSV 안의 기사 본문 칸은 여전히 비정형입니다 — 숫자로 바꿔야 모델에 들어갑니다.
- **바이어 × 기준일 한 줄에 여섯 묶음**: ① 잔액·에이징 ② 결제 행태 ③ 재무비율 ④ 국가위험 ⑤ 환율 ⑥ 뉴스(비정형 → 정형). 라벨 `late_30d`(30일 이내 연체 여부)는 특성 계산에 쓰지 않습니다.

## 2.3.3 [기초 F2-a] 웹 스크래핑 법적 리스크 + HTTP · API {#m233}

2교시 · #19–#22 · 용어 카드 2-9 · 2-7 · 2-8 · 자세히: [기초 지식 F2](../foundations/f2.md)

- <span class="chip chip--f">[기초 F2]</span> **웹은 요청과 응답입니다.** 주소로 요청하면 서버가 상태 코드와 내용을 돌려줍니다 — 200 성공 · 403 출입 금지 · 404 없음 · 429 너무 자주(차단의 신호). 상태 코드는 기술 응답일 뿐 **이용 허락이 아닙니다**.
- **창문 말고 정문으로**: API는 기계용 정문(규칙 · 한도 · 키), 스크래핑은 사람용 창문입니다. 확인 순서 — **API · 오픈데이터 → 이용약관 → robots.txt → 요청 간격 → 보관 범위(제목 · 날짜 · URL · 점수)**.
- **robots.txt는 출입 안내문이지 허가증이 아닙니다**(`User-agent` = 누구, `Disallow` = 못 가는 경로). <span class="chip chip--public">[공개 사례 · RFC 9309]</span> 표준 문서도 robots.txt가 접근 권한을 주는 수단이 아니라고 적습니다. 수집 가능 여부 = 약관 + 법령(저작권 · 부정경쟁 · 개인정보).
- **공개돼 있어도 '가져가는 방법'이 불법을 만듭니다.**

## 2.3.5 AI 감성분석과 위험지수(0–10) 수치화 {#m235}

3교시 · #26–#29 · 용어 카드 2-10 · 2-11 · 띠: 프롬프트 버전

- **'기분'이 아니라 '지급'을 잽니다.** 오늘의 감성 = 일반적인 좋다/나쁘다가 아니라 **바이어의 대금 지급 능력·의사**입니다. '신제품 출시'는 좋은 소식이지만 지급 위험과는 무관하므로 중립입니다. 관점을 지시하지 않으면 AI는 '좋은 기분'을 잽니다.
- **계획서 척도를 그대로 씁니다 — 0–5 부정·위험, 6–10 긍정.** 계획서 변수명 원문: "AI 기반 감성 분석 위험 지수(부정/위험=0~5, 긍정=6~10)".

| 점수 | 앵커 | label |
|---|---|---|
| 0 | 파산 · 회생 신청 확인 | severe(0–2) |
| 1–2 | 심각 — 차입 약정 위반 · 계속기업 의문 · 지급 불능 보도 | severe |
| 3–4 | 뚜렷한 부정 — 대규모 감원 · 공급사 대금 지연 · 신용등급 하향 | high |
| 5 | 약한 부정(경계) — 실적 둔화 전망 · 원가 상승 · 소규모 소송 · 투자·가동 연기 | watch(5만) |
| 6–8 | 중립 · 일상 — 신제품 · 전시회 · 인사 | low(6–10) |
| 9–10 | 지급 위험을 낮춤 — 대형 수주 · 증자 · 신규 대출 · 등급 상향 | low |

- 모델 · 경보용 값은 방향을 뒤집습니다: **`news_risk` = 10 − 점수**(높을수록 위험). 바이어의 30일 지수는 기간 안 점수의 평균이고, **30일 안에 뉴스가 0건이면 5 + `no_news_flag` = 1**로 둡니다.
- **점수보다 기준이 먼저입니다** — 프롬프트에 관점 · 앵커 · 근거 · 형식을 박습니다: 회사 이름으로 외부 지식을 끌어오지 않는다 · `evidence`는 원문 구절 그대로(20단어 이내, 번역 금지) · 애매하면 5로 뭉개지 말고 `confidence`를 낮춘다 · 입력 1행 = JSON 1줄(출력 줄 수 = 입력 행 수 → P2-3으로 검증). <span class="chip chip--field">[현장 사례 · 익명]</span> 먼저 이름이 같은 다른 회사 기사를 거르고, 그다음 본문 감성을 매겼습니다.
- **AI 점수는 정답표와 맞춰 본 뒤에 씁니다.** 골든셋 = 사람이 정답을 단 표본(오늘은 뉴스 앞 100행에서 고른 20건, 15:35 공개). 일치도 = **MAE**(AI − 정답의 절댓값 평균)와 **±2 이내 비율**. AI가 매번 같은 점수를 내는 것(일관성)과 정답에 맞는 것(정확성)은 다릅니다.

## 2.3.6 채권관리 통합파일: 데이터 사전 · 재현 가능한 파이프라인 {#m236}

3교시 · #30–#32(실습 브리핑 #33–#36) · 용어 카드 2-12

- **데이터 사전은 표의 사용설명서입니다** — 각 열의 이름 · 뜻 · 단위 · 출처. 열 이름만으로는 `late_ratio`가 12개월인지 180일인지 알 수 없습니다. `buyer_id`는 가명 ID라 모델 특성으로 쓰지 않습니다(메타).
- **스키마 · 조인 키 — 파일을 잇는 약속**: `buyers.buyer_id = news.buyer_id` → 바이어당 1줄. 표준 스키마는 `buyer_id` 첫 열 · `late_30d` 끝 열 · 영문 snake_case입니다. 열 이름만 같다고 붙지 않습니다 — 단위 · 기준일 · 통화가 같아야 같은 열입니다.
- **같은 입력이면 같은 결과가 나와야 합니다 → 원본은 그대로 두고, 바꾸는 규칙을 파일로 남깁니다.** raw `d2_start.xlsx` → clean `d2_step1.xlsx` → feature `d2_end_features.csv`. 규칙 · 프롬프트 · 사전은 8교시에 커밋합니다. <span class="chip chip--field">[현장 사례 · 익명]</span> 현장 프로젝트마다 같은 4단 흐름이 반복됐습니다 — 수집 → 정제 → AI 해석 → 대시보드.
- **같은 일을 두 도구로** — 막히면 같은 줄의 다른 도구로 갈아탑니다. Orange는 위젯 연결(`.ows`)이, 시트는 수식이 '규칙 문서'가 됩니다.

| 일 | Orange 위젯 | 엑셀 · 구글 시트 | Step |
|---|---|---|---|
| 결측 대체 | Impute — Fixed value(중앙값) · Model-based(kNN k = 1을 Learner에 이으면 1-NN) | `=MEDIAN()` 뒤 `=IF(ISBLANK(x), 중앙값, x)` | 4 · 8 |
| 범주 → 숫자 | Continuize — One-hot | IF로 0/1 열 | 4(보기만) |
| 정규화(비교만) | Preprocess — Normalize [0, 1] · Standardize | `(x − MIN) / (MAX − MIN)` | 4 |
| 기준일 환율 | 전용 위젯 없음 → 시트에서 | `XLOOKUP(…, -1)` | 3 |
| 뉴스 집계 · 병합 | Group by → Merge Data(`buyer_id`) | `COUNTIFS` · `AVERAGEIFS` · `MINIFS` | 8 |
| 저장 | Save Data(.csv) | CSV UTF-8(쉼표로 분리) | 8 |
