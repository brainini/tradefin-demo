## Step 5 안전 수집 점검 {#step5}

<span class="chip chip--f">[기초 F2]</span> **15:00–15:15 (15분)** · 모으기 전에 "가져와도 되는가"를 12항목으로 판단하고 기록한다 — 계획서 '법적 허용 범위 안의 안전한 스크랩'

=== "🟢 Basic"

    **① robots.txt 열기 — 주소창에 직접**

    1. 내 주요 바이어 국가의 뉴스 사이트 1곳을 고릅니다. 떠오르지 않으면 강사가 화면에 띄운 예시 사이트를 씁니다.
    2. 브라우저 주소창에 `사이트주소/robots.txt`를 입력하고 ++enter++ 를 누릅니다(예: `https://www.예시.com/robots.txt`). 글자만 있는 화면이 뜨면 파일이 있는 것(응답 200), '찾을 수 없음'이면 없는 것(404)입니다.
    3. `User-agent: *`(모든 봇) 아래의 `Disallow:` 경로를 **3개** 적어 둡니다. AI 수집 봇 이름(예: `GPTBot`)이 따로 적혀 있는지도 봅니다.

    **② 이용약관에서 금지 문구 찾기**

    4. 사이트 맨 아래 **이용약관**(Terms) 링크를 엽니다.
    5. ++ctrl+f++ 로 `자동` · `수집` · `크롤링` · `복제` · `AI` · `학습`(영문 사이트는 `scrap` · `crawl` · `robot` · `text and data mining`)을 검색합니다. 찾은 조항 번호와 문구를 **원문 그대로 짧게** 적습니다.

    **③ `robots` 시트 — 12항목 O/X/? + 결론 1줄**

    6. `d2_step1.xlsx`에 새 시트 `robots`를 만듭니다.
    7. 아래 표를 마우스로 끌어 선택해 복사하고 `robots` 시트 **A1**에 붙입니다. 고른 사이트를 기준으로 D열에 **O / X / ?**, E열에 근거(어디서 봤나)를 적습니다.

        | # | 항목 | 확인 방법 | O/X/? | 근거 |
        |---|---|---|---|---|
        | 1 | 목적: 사내 분석용인가, 재배포·판매용인가(재배포는 원칙 금지) | 우리 목적 기재 | | |
        | 2 | 약관에 자동수집·크롤링·AI 학습 금지 조항이 있는가(있으면 수집하지 않는다) | 이용약관 검색 | | |
        | 3 | robots.txt의 Disallow · 크롤러 지정을 지키는가 | `/robots.txt` | | |
        | 4 | 로그인 · 유료벽 · CAPTCHA · IP 차단을 우회하지 않는가(VPN · IP 분산 금지, 정체를 밝힌다) | 접근 방식 | | |
        | 5 | 공식 API · 오픈데이터(GDELT · BIG KINDS · 공공데이터포털)가 있으면 그것을 쓰는가 | API 유무 | | |
        | 6 | DB의 '상당한 부분'을 반복 · 체계적으로 복제하지 않는가(필요한 필드 · 기간만) | 수집 범위 | | |
        | 7 | 요청 간격을 두는가(예: 초당 1회 이하) | 설정값 | | |
        | 8 | 기사 속 개인 이름 · 연락처를 바로 지우거나 가명 처리하는가 | 처리 규칙 | | |
        | 9 | 기사 전문을 저장 · 공유하지 않고 제목 · 날짜 · URL · 점수만 보관하는가 | 보관 항목 | | |
        | 10 | 해외 사이트라면 TDM 거부 표시(EU) · 약관(미국) 위험을 확인했는가 | 사이트 국가 | | |
        | 11 | 수집 일시 · 출처 · 약관/robots 확인 결과를 기록으로 남기는가 | 기록 양식 | | |
        | 12 | AI 도구에 넣기 전 개인정보를 지우고 학습 설정을 껐는가 | 설정 화면 | | |

    8. 표 아래에 **결론 1줄**을 씁니다 — `API 사용` / `수집 불가` / `수동 열람만` 중 하나와 이유(예: `수동 열람만 — 약관 제○조가 자동수집 금지`). 정답이 하나가 아닙니다. 결론이 2 · 3 · 5번 칸과 맞으면 됩니다.

    **④ 오늘 쓰는 뉴스의 출처 기록**

    9. 오늘 점수화하는 뉴스는 강사가 준비한 `d2_news.csv`입니다. `robots` 시트 아래에 출처를 적습니다: `과정 제작 합성 뉴스 · CC BY 4.0 · 2026-10-15 받음`.
    10. (선택) 비교: 뉴스 RSS 피드 하나의 저작권 문구(예: '개인 · 비상업 용도만')를 읽고, 실습 수집원으로 쓰지 않는 이유를 1줄 씁니다.

    ??? tip "AI로 하는 법 — 약관 조항은 원문 인용 표로"
        약관 전문을 붙여 넣고 `자동수집·크롤링·AI 학습을 금지하는 조항을 원문 그대로 인용해 표(조항 번호 · 원문 · 뜻)로 보여 줘. 없으면 "없음"이라고 써.`라고 보냅니다. **판단은 사람이 합니다** — 인용된 원문을 약관 페이지에서 ++ctrl+f++ 로 찾아 확인한 뒤 O/X를 고릅니다.

=== "🔵 Standard"

    **자사 바이어 공개 뉴스 5–10건 — 사람이 열람, 제목 · 날짜 · URL만**

    1. 내 주요 바이어(가명으로 부를 이름을 먼저 정합니다, 예: `유럽 유통 A`)에 관한 공개 뉴스를 검색해 **사람이 직접** 5–10건 엽니다. 자동 수집 도구는 쓰지 않습니다.
    2. 내 PC의 별도 파일(예: `my_news_private.xlsx`)에 **제목 · 날짜 · URL**만 적습니다. 본문은 복사하지 않습니다(12항목 9번).
    3. 바이어 실명은 이 파일에만 두고, Step 6에서 AI에 넣을 때는 가명으로 바꿉니다. 이 파일은 저장소에 올리지 않습니다 — 제출 폼에만 냅니다.

=== "🟣 Challenge"

    **수집 설계서 5줄 — 실제 호출 없이**

    1. GDELT의 이용 조건과 DOC API 문서를 읽습니다(인용 · 링크 표기 조건, 조회 기간, 호출 제한).
    2. `robots` 시트 아래에 '수집 설계서' 5줄을 씁니다: ① 호출 간격 ② 보관 항목 ③ 인용 표기 ④ 기간 ⑤ 개인정보 처리.
    3. 오늘은 API를 실제로 부르지 않습니다 — 강의장 전원이 같은 인터넷 주소를 써서 차단될 수 있습니다. 설계서만 남깁니다.

## Step 6 위험지수 점수화 {#step6}

**15:15–15:45 (30분)** · 뉴스 100행을 계획서 척도로 점수화하고, 형식을 검증해 CSV로 만든다

=== "🟢 Basic"

    **① 뉴스 앞 100행 · 5열 준비**

    1. AI 서비스의 **학습 설정이 꺼져 있는지** 다시 봅니다(12항목 12번) → [사전 준비 3번](../setup.md#ai-training).
    2. `d2_news.csv`를 엑셀로 엽니다(한글이 깨지면 **데이터** → **텍스트/CSV에서** → **65001: 유니코드(UTF-8)** → **로드**). 최신순이라 2–101행이 앞 100행입니다.
    3. 점수에 쓰지 않는 열 3개 — `ref_window`(C) · `lang`(E) · `source_type`(H) — 의 **열 머리 글자**를 ++ctrl++ 를 누른 채 클릭 → 마우스 오른쪽 → **삭제**. 남은 5열이 `news_id` · `buyer_id` · `date` · `headline` · `body_short`인지 봅니다. (이 창은 나중에 **저장 안 함**으로 닫습니다 — 원본 파일은 그대로 둡니다.)

    **② 워밍업 10건 → P2-2 50행씩 두 번**

    4. AI 화면에서 **새 채팅**을 열고 **P2-2**를 붙여 넣습니다.

        ??? example "P2-2 뉴스 지급위험 점수(0–10, JSON Lines) — 펼쳐서 복사"
            [프롬프트 라이브러리에서 P2-2 보기(앵커 · 흔한 실패)](../prompts/day2.md#p2-2)

            --8<-- "labs/day2/prompts.md:p2-2"

    5. **워밍업**: 맨 아래 `{50행 붙여넣기}` 자리에 **A1:E11**(머리글 + 앞 10행)을 복사해 붙이고 보냅니다. 답이 **한 행에 JSON 한 줄**, 10줄인지 봅니다. 줄글 · 설명 · 코드블록 표시가 섞이면 `JSON Lines만, 입력 1행당 1줄로 다시 출력하라.`를 보냅니다. 앵커와 다르게 매긴 것 같은 줄이 있으면 [이론 2.3.5](theory.md#m235)의 표와 비교해 봅니다.
    6. **배치 1**: 같은 채팅에 아래 '다음 배치' 두 줄을 붙이고, 둘째 줄 자리에 **A1:E51**(머리글 + 1–50행)을 붙여 보냅니다. 워밍업 10건이 다시 들어가니, 같은 뉴스의 점수가 워밍업 때와 같은지도 봅니다(일관성).

        ??? example "P2-2 다음 배치(같은 채팅에 이어서) — 펼쳐서 복사"
            --8<-- "labs/day2/prompts.md:p2-2-next"

    7. **배치 2**: 같은 방법으로 머리글 + **52–101행**(51–100번째 뉴스)을 보냅니다. 머리글 줄은 1행을 복사해 붙인 뒤 52–101행을 이어 붙입니다.

    **③ P2-3 — 줄 수 · 범위 · label · 근거 검증 → CSV**

    8. 같은 채팅에 **P2-3**을 붙여 보냅니다.

        ??? example "P2-3 JSON 검증과 CSV 변환 — 펼쳐서 복사"
            [프롬프트 라이브러리에서 P2-3 보기](../prompts/day2.md#p2-3)

            --8<-- "labs/day2/prompts.md:p2-3"

    9. 답의 **위반 표**를 봅니다 — 빠진 `news_id` · 0–10 밖의 점수 · 점수와 맞지 않는 label(severe 0–2 · high 3–4 · watch 5 · low 6–10) · 원문에 없는 evidence. 위반 행은 AI가 다시 채점했는지 확인합니다.
    10. CSV를 받습니다. 파일 받기 버튼이 있으면 내려받아 `D2` 폴더에 `d2_news_scored.csv`로 저장합니다. 코드블록으로 왔으면 복사 → 메모장 → **다른 이름으로 저장** → `d2_news_scored.csv` · **모든 파일(\*.\*)** · **UTF-8**.

    **④ evidence 2건을 원문에서 확인**

    11. 메모장으로 `d2_news.csv`를 엽니다(마우스 오른쪽 → **연결 프로그램** → **메모장**).
    12. AI 답의 `evidence` 2개(점수가 낮은 것 하나, 아무거나 하나)를 복사해 ++ctrl+f++ 로 찾습니다. 같은 `news_id` 줄에 그대로 있으면 ✔, 없으면 ✘ — ✘면 그 행을 P2-3의 3번 점검으로 다시 채점하게 합니다. evidence는 **번역하지 않은 원문**이어야 찾아집니다.

    **⑤ `news` 표와 `news_risk` 열**

    13. `d2_step1.xlsx`에서 **데이터** → **텍스트/CSV에서** → `d2_news_scored.csv` → **UTF-8** → **로드**. 생긴 표의 이름을 `news`로 바꿉니다(**테이블 디자인** → **표 이름**).
    14. 표 오른쪽 빈 열 1행에 `news_risk`, 2행에 `=10-[@news_sent_0_10]`. 높을수록 위험한 방향입니다.
    15. 빈 칸에 `=COUNT(news[news_sent_0_10])`(100이어야 함) · `=MIN(news[news_sent_0_10])` · `=MAX(news[news_sent_0_10])`(0–10 안)을 넣어 확인합니다. ++ctrl+s++.

=== "🔵 Standard"

    **300행 전체 + 자사 뉴스(제목만)**

    1. Basic ②를 6배치(50행 × 6)로 늘려 300행 전체를 점수화합니다. 배치마다 같은 채팅을 쓰되, 답이 흐트러지면 새 채팅에 P2-2를 다시 붙여 이어 갑니다.
    2. 자사 뉴스 5–10건은 **새 채팅**에서 P2-2로 따로 점수화합니다. 입력은 `news_id`(예: `M01`) · `buyer_id`(가명) · `date` · `headline`(제목)만 넣고 `body_short`는 빈칸으로 둡니다. 회사 실명은 가명으로 바꿉니다.
    3. 자사 점수표(제목 · 날짜 · URL · 점수)는 내 PC 파일에만 두고, 제출 폼에만 냅니다 — 저장소에 올리지 않습니다.

=== "🟣 Challenge"

    **Colab에서 배치 점수화 + GDELT 톤 변환 공식**

    1. 노트북의 LLM 점수화 칸: Colab의 내장 AI 기능(`from google.colab import ai`)으로 P2-2와 **같은 본문**을 50행씩 보냅니다. 함수 이름과 쓸 수 있는 모델은 칸 안 안내를 따릅니다(자주 바뀝니다).
    2. 답의 줄마다 `json.loads`로 읽고, 실패한 줄 · 빠진 `news_id`만 다시 보냅니다(재시도). 줄 수 = 입력 행 수가 될 때까지.
    3. **GDELT 톤 → 0–10**: 톤은 대개 −20~+20 안에 있습니다. −10~+10에서 자른 뒤 0–10으로 바꿉니다 — 엑셀 `=(MAX(-10,MIN(10,톤))+10)/2`. 예시 값 −15 · −4 · 0 · +6을 넣어 직접 계산하고, 왜 −100~+100 전체로 바꾸면 값이 가운데에 몰리는지 한 줄로 씁니다(오늘 데이터에는 GDELT 행이 없습니다 — 공식만 연습합니다).
    4. Colab AI 기능의 입력은 사람 검토자가 볼 수 있고 오래 보관될 수 있습니다 — 합성 데이터만 넣습니다.

## Step 7 일치도 {#step7}

**15:45–15:50 · 16:00–16:15 (20분)** · AI 점수를 사람 정답과 비교해 "얼마나 믿을지"를 숫자로 정한다

=== "🟢 Basic"

    **① 15:35 골든셋 받기 → 정답 붙이기**

    1. 15:35에 이 페이지를 새로 고치면 [입력 파일](#files) 표의 `d2_news_answer.csv`에 **받기** 링크가 생깁니다. 받아서 `D2` 폴더에 둡니다.
    2. `d2_step1.xlsx`에서 **데이터** → **텍스트/CSV에서**로 불러오고 표 이름을 `ans`로 바꿉니다. 20행, 열은 `news_id` · 정답 점수(`news_sent_0_10_true`) · 정답 label · 메모 등입니다.
    3. `news` 표 오른쪽에 두 열을 만듭니다.

        | 열 이름 | 수식 |
        |---|---|
        | `truth` | `=XLOOKUP([@news_id],ans[news_id],ans[news_sent_0_10_true],"")` |
        | `abs_err` | `=IF([@truth]="","",ABS([@news_sent_0_10]-[@truth]))` |

    **② MAE · ±2 이내 비율 → `news_review`**

    4. 새 시트 `news_review`를 만들고 세 칸을 계산합니다.

        | 칸 | 수식 | 뜻 |
        |---|---|---|
        | 대조 건수 | `=COUNT(news[abs_err])` | 20이어야 합니다(적으면 점수화가 빠진 `news_id`가 있다) |
        | MAE | `=AVERAGE(news[abs_err])` | 평균 오차 — 작을수록 정답에 가깝다 |
        | ±2 이내 비율 | `=COUNTIF(news[abs_err],"<=2")/COUNT(news[abs_err])` | 정답과 2점 안에 든 비율 |

    **③ 오차 큰 3건 — '누가 맞았나'**

    5. `news` 표의 `abs_err` ▼ → **숫자 필터** → **크거나 같음** → `4`. 3건이 안 되면 필터를 풀고 `abs_err`를 **내림차순 정렬**해 위에서 3건을 고릅니다.
    6. 3건마다 `news_review`에 적습니다: `news_id` · 헤드라인 · AI 점수 · 정답 · **누가 맞았나**(AI / 정답 / 애매) · **이유 1줄**(어느 앵커에 해당하나). 내 판단을 먼저 쓰고, 그다음에 `ans` 표의 메모를 읽어 봅니다.
    7. ++ctrl+s++.

=== "🔵 Standard"

    **100건 대조 + 짝과 재현성**

    1. 15:35에 공개되는 정답 파일은 `d2_news_answer.csv`(골든셋 20건) **하나**입니다 — 100행 채점본은 따로 공개하지 않습니다. 100행을 모두 점수화했다면 그 안의 골든셋 20건으로 Basic과 같은 MAE · ±2 비율을 내고, 정답이 없는 나머지 80행은 아래 2의 재현성(짝과 점수 차)으로 봅니다. 두 숫자(일치도 · 재현성)가 서로 다른 이야기를 하면 어느 쪽을 더 믿을지 한 줄로 씁니다.
    2. 짝과 **같은 50행**을 각자 따로 점수화했다면, 두 사람의 점수를 `news_id`로 붙여 **두 사람 점수 차의 절댓값 평균**을 구합니다. 같은 프롬프트 · 같은 입력인데 얼마나 달랐나 — 재현성의 숫자입니다.

=== "🟣 Challenge"

    **프롬프트 두 판 비교 — P2-2 v1 vs 내가 고친 v2**

    1. 오차가 큰 사례를 보고 P2-2의 앵커나 규칙 한 줄을 고쳐 **v2**를 만듭니다(예: 국가 · 업황 뉴스의 범위 문장).
    2. 같은 100행을 v2로 다시 점수화하고 골든셋 MAE를 v1과 비교합니다.
    3. 바꾼 내용과 이유를 `P2-2_감성점수.md`의 변경 기록에 한 줄로 적습니다 — 8교시에 커밋합니다. 골든셋에 맞추려고 정답 문장을 프롬프트에 넣지는 않습니다(시험 문제를 보고 푸는 셈).

## Step 8 통합 · 저장 — 계획서 [결과 파일 저장] {#step8}

!!! info "뉴스 창 = 기준일 전 30일 (2026-08-01 초과 ~ 2026-08-31 이하)"
    수식 조건은 `">"&(AsOf-30)`과 `"<="&AsOf`입니다. `>=`를 쓰면 31일 창이 됩니다. 기준일 뒤 뉴스를 쓰면 라벨 기간의 정보가 특성에 들어가는 **누수**입니다.

=== "🟢 Basic"

    **① `features` 표에 뉴스 4열**

    1. `features` 시트(표 `feat`)에서 `late_30d` 열의 칸 하나를 마우스 오른쪽 → **삽입** → **왼쪽에 표 열 삽입**을 4번 합니다. `late_30d`가 맨 끝에 남습니다.
    2. 새 4열의 1행에 이름, 2행에 수식을 넣습니다(`AsOf`는 `fx_param`의 이름 정의 — 2026-08-31인지 다시 봅니다).

        | 열 이름 | 수식 |
        |---|---|
        | `news_cnt_30d` | `=COUNTIFS(news[buyer_id],[@buyer_id],news[date],">"&(AsOf-30),news[date],"<="&AsOf)` |
        | `news_sent_0_10_30d` | `=IF([@news_cnt_30d]=0,5,AVERAGEIFS(news[news_sent_0_10],news[buyer_id],[@buyer_id],news[date],">"&(AsOf-30),news[date],"<="&AsOf))` |
        | `no_news_flag` | `=--([@news_cnt_30d]=0)` |
        | `news_risk_30d` | `=10-[@news_sent_0_10_30d]` |

        - 30일 안에 뉴스가 없으면 점수는 **5(중립)** + `no_news_flag` = 1입니다. '뉴스 없음'을 '좋은 뉴스'로 착각하지 않게 표시를 남깁니다.
    3. `check` 시트에 **뉴스가 있는 바이어 수**를 적습니다: `=COUNTIF(feat[news_cnt_30d],">0")`.

    **② 데이터 사전 초안 (P2-4)**

    6. ++ctrl+s++ 로 `d2_step1.xlsx`를 저장합니다.

## 흔한 오류와 해결 {#troubleshooting}

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | robots.txt 주소에서 '찾을 수 없음' | 그 사이트에 파일이 없다(404) 또는 주소 오타 | 사이트 첫 화면 주소(도메인) 바로 뒤에 `/robots.txt`. 없으면 3번 칸에 '없음' — 약관 판단이 더 중요해집니다 |
| 2 | AI 답 앞뒤에 설명이나 코드블록 표시(백틱 세 개)가 붙어 CSV가 안 된다 | 형식 지시를 놓쳤다 | P2-3으로 다시 검증하거나 `JSON Lines만, 머리말 없이 다시 출력하라.` |
| 3 | 50행을 넣었는데 47줄만 돌아왔다 | 긴 출력에서 줄이 빠졌다 | P2-3의 '빠진 news_id 목록'만 다시 채점 · 배치를 30행으로 줄입니다 |
| 4 | 점수가 거의 다 5 · 7에 몰렸다 | 애매하면 가운데로 뭉갰다 | `애매하면 5로 뭉개지 말고 confidence를 낮춰라. 앵커 표를 다시 읽고 점수화하라.` |
| 5 | 한국어 · 스페인어 뉴스의 evidence가 영어로 왔다 | AI가 번역했다 | `evidence는 번역하지 말고 원문 구절 그대로 넣어라.` — 원문이어야 ++ctrl+f++ 로 찾힙니다 |
| 6 | 받은 CSV의 한글이 깨진다 | BOM 없는 UTF-8 | 더블클릭 대신 **데이터** → **텍스트/CSV에서** → 65001 UTF-8 → **로드** |
| 7 | `truth`가 모두 빈칸 | `news_id` 표기가 다르다(공백 · 대소문자) 또는 `ans` 표 이름이 다르다 | 두 표의 `news_id`를 하나씩 비교 · **테이블 디자인**에서 표 이름 확인 |
| 8 | 대조 건수가 20보다 적다 | 골든셋 20건 중 점수화하지 않은 뉴스가 있다 | 빠진 `news_id`만 P2-2로 점수화해 `news` 표에 추가 |
| 9 | `news_cnt_30d`가 모두 0 | `news[date]`가 글자로 읽혔다(왼쪽 정렬) | `date` 열 선택 → **데이터** → **텍스트 나누기** → **마침**으로 날짜로 바꾸기 |
| 10 | `news_sent_0_10_30d`에 **#DIV/0!** | 창 안에 뉴스가 없는데 AVERAGEIFS를 했다 | 위 표의 `IF([@news_cnt_30d]=0,5,…)` 수식을 그대로 씁니다 |
| 11 | 뉴스 있는 바이어가 예상보다 많다 | `>=`(31일 창)이나 기준일 2026-09-30을 썼다 | 조건을 `">"&(AsOf-30)` · `"<="&AsOf`로, `AsOf`를 2026-08-31로 |
| 12 | 저장한 CSV의 첫 열이 `buyer_id`가 아니다 | 다른 시트에서 저장했거나, Orange Save Data로 저장했다(Orange는 `late_30d` → `buyer_id` → 특성 순서로 저장한다) | `features` 시트를 연 채 다시 **CSV UTF-8**로 저장 |
| 13 | CSV를 다시 열었더니 수식이 다 사라졌다 | CSV는 값만 저장한다 | 정상입니다. 수식은 `d2_work__T조-번호.xlsx`에 남아 있습니다 |

더 많은 증상은 [FAQ·트러블슈팅](../faq.md)에 있습니다.
