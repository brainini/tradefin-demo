## Step 2 할인율 · NPV 검산 {#step2}

**13:15–13:40 (25분)** · 등급별 위험조정 할인율과 부보 판정이 오전 이론과 같은지, 은행 견적과 어떻게 비교되는지 확인한다

=== "🟢 Basic"

    **① `03_RateBuild` — 등급별 할인율 검산표**

    1. `03_RateBuild` 시트를 엽니다. 위쪽 검산표(USD 100,000 · 90일)에서 등급별 **r 무보험 · r 부보**를 [이론 4.3.1의 표](theory.md#m431)와 맞춰 봅니다.

        | 등급 | r 무보험 | r 부보 | 판정 |
        |---|---|---|---|
        | S | 5.35% | 6.28% | 무보험 유리 |
        | A | 6.45% | 7.21% | 무보험 유리 |
        | B | 8.45% | 8.19% | 부보 유리 |
        | C | 12.55% | 10.90% | 부보 유리 |

    2. 칸 서식이 소수 둘째 자리까지 안 보이면 칸을 선택하고 **홈** → **자릿수 늘림**을 누릅니다.
    3. 표 아래 '차트용 구성' 칸에서 할인율이 ① Term SOFR 3M ② 은행 가산 ③ 보험료(연환산) ④ EL로 쌓이는 것을 봅니다 — **돈의 값 + 위험의 값**.
    4. 손익분기 규칙을 한 줄로 적습니다: "보험료(연환산) < PD × LGD × 보상비율이면 부보 — A와 B 사이에서 바뀐다."

    **② `05_NPV` — 은행 견적 대조**

    5. `05_NPV` 시트 위쪽 '은행 견적 대조'를 봅니다: 매입 금액 USD 100,000 · 92일 · 하나은행 고시 환가료율(92일) → **환가료 USD 1,669.54** · 매입수수료(₩20,000 ÷ 원/달러) → **연환산 실효 6.59%**. 오른쪽 칸에 **✔ G03 일치**가 보이면 맞습니다.
    6. 31일이면 환가료가 얼마인지(같은 시트의 '31일이면' 줄)도 봅니다 — 기간이 짧을수록 은행 매입 비용이 줄어듭니다.
    7. 해석 한 줄: 실효 6.59%가 A–B등급의 '자금비용 + EL' 구간(6.45–8.45%) 안에 드는가? → 은행 매입이 우리 할인율과 비교해 어떤지 메모합니다.
    8. 아래쪽 바이어별 표에서 미결 잔액이 큰 바이어 한 곳의 NPV 무보험 · 부보와 부보 판정을 읽어 봅니다. ++ctrl+s++.

=== "🔵 Standard"

    **자사 견적 · 요율로 교체**

    1. 거래 은행의 환가료 견적(있으면)과 자사 '보험료 납부통보문'의 요율 · 결제기간(익명)을 `01_Params`의 노란 칸(`Hana92` 등은 파랑이라 바꾸지 않고, 비교용 새 칸을 만들어 넣습니다)에 메모합니다.
    2. K-SURE 개별보험 요율표는 비공개라 오늘 보험료는 [가정]입니다 — 자사 통보문의 요율이 가장 좋은 데이터입니다. 자사 요율로 `Prem_*`(노랑)을 바꿔 부보 판정이 어느 등급에서 바뀌는지 봅니다.

## Step 3 해 찾기로 한도 최적화 {#step3}

**13:40–13:50 · 14:00–14:25 (35분)** · 손실은 줄이고 매출은 높이는 바이어별 안전 여신 한도를 선형계획(LP)으로 산정한다

=== "🟢 Basic"

    **① `10_LimitLP` 구조 보기**

    1. `10_LimitLP` 시트를 엽니다. **C2** = 목적함수 `Obj`(=SUMPRODUCT(coef, L)) · **F5:F154** = 결정변수 `L`(주황, 해 찾기가 채움) · D열 UB 상한 · E열 LB 하한 · G열 coef · I열 현행 한도 · L열 승인 표시.
    2. 오른쪽 **제약 표**(T–Y열)에서 ① 총허용익스포저 ② 미부보 EL 예산 ④ B등급 비중과 아래 ③ 국가 한도 블록(20개국)을 봅니다. '걸림?' 칸은 해를 찾은 뒤에 채워집니다.

    **② 해 찾기 대화상자**

    3. **데이터** → **해 찾기**를 누릅니다. 워크북에 모델이 저장돼 있어 칸이 이미 채워져 있을 수 있습니다. 비어 있으면 시트 오른쪽 아래 **'해 찾기 입력표'**(T44 근처)를 보고 그대로 넣습니다.

        | 칸 | 값 |
        |---|---|
        | 목표 설정 | `$C$2` → **최대값** |
        | 변수 셀 변경 | `$F$5:$F$154` |
        | 제한 조건 1 | `$F$5:$F$154 <= $D$5:$D$154` (L ≤ UB) |
        | 제한 조건 2 | `$F$5:$F$154 >= $E$5:$E$154` (L ≥ LB) |
        | 제한 조건 3 | `$U$5 <= $W$5` (총 한도 ≤ 총허용익스포저) |
        | 제한 조건 4 | `$U$6 <= $W$6` (미부보 EL ≤ EL 예산) |
        | 제한 조건 5 | `$Z$12:$Z$31 <= $Y$12:$Y$31` (국가별 사용 ≤ 국가 한도, 20칸 한 줄) |
        | 제한 조건 6 | B등급 비중 줄(`$U$7 <= $W$7`) |

    4. **제한되지 않는 변수를 음이 아닌 수로 설정** ✔ → **해법 선택**: **단순 LP** → **해 찾기**.

    **③ 결과와 보고서**

    5. 결과 창에 **"해 찾기가 해를 찾았습니다. 모든 제한 조건과 최적 조건이 만족되었습니다."**가 나오는지 봅니다 → **해 찾기 해 보존** · 오른쪽 **보고서**에서 **해답**과 **민감도**를 클릭해 선택 → **확인**.
    6. 새 시트 **민감도 보고서**를 엽니다. 아래 '제한 조건' 표의 **잠재 가격**에서 0이 아닌 줄 하나를 골라 내 말로 한 줄 적습니다: "○○ 제약을 1달러 늘리면 목적함수(연간 기대이익)가 ○달러 늘어난다." 잠재가격 0 = 그 제약은 지금 걸려 있지 않다(꺼도 해가 그대로)는 뜻입니다.
    7. `10_LimitLP` 제약 표의 **걸림?** 칸에서 어떤 제약이 걸렸는지 봅니다. 민감도 보고서의 잠재가격을 제약 표 옆 칸(Z5:Z7 · 국가 블록 AC12:AC31)에 옮겨 적어 두면 블록 B 리포트 입력에 그대로 쓰입니다.

    **④ 사람이 결정할 곳 표시 확인**

    8. L열 **승인 표시**를 필터로 봅니다: '감액 30%↑ — 사람 승인 필요' 행이 있는지, C등급 O/A · L/C · 선수금 바이어의 L이 **0**인지(대상 아님 또는 UB = 0) 확인합니다. 한도 변경은 모델이 아니라 **사람이 최종 승인**합니다.
    9. N열 '전결권자'로 금액대별 승인자(채권관리팀장 · 영업본부장 · 대표이사)를 봅니다. ++ctrl+s++.

    **⑤ 제약 실험 1회**

    10. **데이터** → **해 찾기** → 제한 조건 목록에서 ④(EL 예산) 또는 ⑤(국가 한도) 줄을 골라 **삭제** → **해 찾기** → 목적함수(C2)가 얼마나 바뀌고 어느 바이어 · 나라로 한도가 몰리는지 메모 한 줄.
    11. 실험이 끝나면 삭제한 제약을 **추가**로 다시 넣고 한 번 더 **해 찾기**를 눌러 원래 해로 돌아옵니다. 보고서는 다시 만들지 않아도 됩니다.

=== "🔵 Standard"

    **최적화 코드 매칭 — 자사 규칙 1개 추가 · 제약 해석**

## 흔한 오류와 해결 {#troubleshooting}

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | 데이터 탭에 **해 찾기**가 없다 | 추가 기능이 꺼져 있다 · 웹 엑셀 | [Step 1 ①](#step1) 순서로 켜기 · 웹 엑셀이면 **Frontline Solver App**(삽입 → 추가 기능) 또는 구글 시트 + OpenSolver(NEOS 서버 옵션은 쓰지 않음 — 모델이 공개됨) |
| 2 | "선형 조건이 충족되지 않았습니다" | 결정변수(F열)에 IF · MIN · MAX · ROUND를 걸었다 | F열은 숫자만. 판단은 UB · LB · coef 회색 열이 하고, 변수에는 SUMPRODUCT만 |
| 3 | "해를 찾을 수 없습니다(실행 불가능)" | 하한 > 상한, 또는 국가 한도 < 그 나라 전략 바이어 최소 한도 합 | LB = MIN(…, UB)인지 · 노란 칸을 바꿨다면 되돌리고 다시 실행 |
| 4 | 변수 셀이 너무 많다는 오류 | 200개 초과 범위를 골랐다 | `$F$5:$F$154`(150칸)만 |
| 5 | 해가 무한대로 발산한다 | UB 제약을 빠뜨렸거나 '음이 아닌 수' 체크를 해제했다 | 제약 목록 6줄과 체크 상자 확인 |
| 6 | 할인율이 404.7%처럼 터무니없다 | 금리를 4.047(퍼센트 숫자)로 입력했다 | 파라미터 칸은 `0.04047`(백분율 서식)로 통일 |
| 7 | 붙여넣기 뒤 회색 열에 #VALUE! | CSV를 ++ctrl+v++ 로 붙여 서식 · 형식이 섞였다 | ++ctrl+z++ → ++ctrl+alt+v++ → **값**으로 다시 · 안 되면 합류용(채운 판) |
| 8 | 데이터 표 1,000행이 느리고 값이 계속 바뀐다 | RAND 재계산 | **수식** → **계산 옵션** → **데이터 표를 제외하고 자동** · 보고할 숫자는 값으로 옮겨 적는다 |
| 9 | 몬테카를로 숫자가 ++f9++ 를 눌러도 그대로 | 드롭다운만 바꾸고 데이터 표가 갱신되지 않았다 | ++f9++ 를 한 번 더 · 계산 옵션 확인 |
| 10 | 민감도 보고서가 안 생긴다 | 결과 창에서 보고서를 고르지 않았거나 해법이 단순 LP가 아니다 | 해법 **단순 LP**로 다시 실행 → 보고서 **민감도** 클릭 |
| 11 | 웹 엑셀에서 연 파일에 해 찾기 모델이 없다 | 웹 엑셀은 해 찾기 모델을 다루지 않는다 | '해 찾기 입력표'의 값을 Solver App에 그대로 넣는다 |
| 12 | Colab PuLP 결과가 엑셀과 다르다 | 최신판(4.x)을 설치했거나, 엑셀에서 저장하지 않은 파일을 올렸다 | PuLP 3.3.2로 고정 · 엑셀에서 저장한 뒤 업로드 |

더 많은 증상은 [FAQ·트러블슈팅](../faq.md)에 있습니다.
