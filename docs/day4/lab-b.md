## Step 5 조기 경보 — 정본 사다리를 걸고 한도에 반영 {#step5}

**15:00–15:25 (25분)** · 약관 규칙으로 위기 바이어를 후보로 올리고, 선적 보류를 한도에 반영한다

!!! info "정본 경보 사다리"
    D-3 사전 안내 → D+7 친절한 리마인더 → D+15 단호한 통지 → **D+30 최종 통지 + 선적 보류**(약관 제7조①2호 연속수출 면책) → **결제기일 + 1개월 이내 K-SURE 사고발생통지**(제21조② · 사람이 결정). 상시: 파산신청 등 인지 → 즉시 선적 중단 · 결제조건 · 결제일 변경 → 10영업일 이내 서면 통지 · 계좌 변경 요청 → 사기 의심(콜백 확인 전 대금 안내 중단).

=== "🟢 Basic"

    **① 기준일과 인보이스 단위 열**

    1. 워크북의 `13_EarlyWarning` 시트를 엽니다. 위쪽 `AsOf`가 **2026-09-30**인지 확인합니다(`01_Params`의 이름 정의).
    2. 인보이스 표(미결 인보이스 ≤ 300행)의 회색 열을 왼쪽부터 읽습니다: `dpd`(기준일 − 결제기일) · `stage`(사다리 단계) · `notice_deadline`(결제기일 + 1개월) · `notice_days_left` · `ksure_alert` · `export_notice_by` · `terms_notify_by` · `fraud_alert`.
        - `notice_deadline`이 46000대 숫자로 보이면 칸 서식을 **날짜**로 바꿉니다.

    **② 단계별 건수 · 금액 → 경보표**

    3. 시트 오른쪽 **단계 요약**(단계 · 건수 · 금액(USD))에서 D-3 · D+7 · D+15 · D+30 · 모니터링의 건수와 금액을 읽어, 시트 옆 빈 칸에 '경보표'로 옮겨 적습니다.
    4. `stage` 열 ▼ 필터로 **D+30 최종통지 · 선적보류**만 걸러 봅니다. 조건부 서식 색(D+30 빨강 · D+15 주황 · D+7 노랑)과 글자가 함께 보이는지 봅니다.

    **③ 선적 보류 → 한도 0 → 해 찾기 다시**

    5. 바이어 단위 요약(오른쪽 `buyer_id` 표)의 `ship_hold`가 **'선적 보류'**인 바이어를 필터로 모아 목록을 적습니다. 판단 기준은 '결제기일 뒤 30일이 지난 미결(L/C 제외)' 또는 '파산 인지'입니다.
    6. `02_Buyers`에서 그 바이어들의 **UB(상한)가 0**인지 확인합니다 — 경보 시트가 한도 시트로 이어져 있습니다.
    7. `10_LimitLP` → **데이터** → **해 찾기** → **해 찾기**를 한 번 더 눌러, 선적 보류가 반영된 해로 다시 풉니다. `escalate` 칸의 '여신 한도 동결 제안(사람 승인)'을 확인합니다.

    **④ K-SURE 통지 기한 · 사기 · 조건 변경**

    8. `ksure_alert` 필터로 **'통지 기한 임박 — 사람 결정'**과 **'통지 기한 경과 — 즉시 확인'** 건을 따로 적습니다. 통지 여부는 사람이 결정합니다 — 경보표에는 '권고(사람 승인 전)'로 씁니다.
    9. `fraud_alert`(계좌 변경 요청)와 `terms_notify_by`(결제조건 변경) 칸을 봅니다. 오늘 데이터는 0건이 정상입니다 — 6일차 위기 카드에서 바뀝니다. `fraud_signals.md`를 열어 계좌 변경 · 유사 도메인 · 제3국 선적 같은 사기 신호를 한 번 읽어 둡니다. ++ctrl+s++.

=== "🔵 Standard"

    **자사 보험 운영방식으로**

    1. 자사가 쓰는 단기수출보험 운영방식을 고릅니다 — **개별**(수출통지: 수출일부터 10영업일) 또는 **포괄 · 준포괄**(선적 다음 달 20일).
    2. 인보이스 표의 `insurance_type` 칸을 그 방식으로 바꿔 `export_notice_by`가 어떻게 달라지는지 봅니다(바꾸기 전 값은 메모).
    3. 내 회사의 실제 보고 라인(예: 채권 담당 → 팀장 → 본부장)에 맞춰, 경보 단계마다 '누가 · 언제까지 · 무엇을 확인하나'를 한 줄씩 씁니다.

=== "🟣 Challenge"

    같은 사다리를 Python 함수로 옮겨(`stage(dpd)`, `notice_deadline = due + 1개월`) `d4_open_inv.csv`에 적용하고, 엑셀의 단계별 건수와 같은지 대조합니다. 월말 날짜(예: 1월 31일 + 1개월)의 처리 차이를 한 줄로 적습니다.

        | 단계 | 입력 파일 | 출력 파일 | 실행 방식 | 사람 검토 지점 | 멈춤 규칙 |
        |---|---|---|---|---|---|
        | ① 집계 | `d4_end_limits`(경보 · 한도 · 시나리오) | `14_ReportInput` 표 5개 | | | |

    6. 표 아래 한 줄: 이 파이프라인을 '위기 바이어 포착 → 경영진 즉시 보고'로 걸려면 어떤 조건에서 실행하나? 저장합니다.

## 흔한 오류와 해결 {#troubleshooting}

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | `notice_deadline`이 46000대 숫자로 보인다 | 칸 서식이 일반 | 칸 서식 → **날짜** |
| 2 | 선적 보류 바이어의 UB가 0이 아니다 | 해 찾기를 다시 돌리지 않았거나 경보 시트를 고쳤다 | `02_Buyers`의 `ship_hold` 열이 경보 시트와 이어져 있는지 확인 → 해 찾기 다시 |
| 3 | '최장 연체일' 칸이 #NAME? | 엑셀 2016(MAXIFS 없음) | 표시만의 문제 — 선적 보류 판정 · 한도는 정상입니다. 엑셀 365 · 웹이면 사라집니다 |
| 4 | 리포트에 입력에 없는 숫자(합계 · 비중)가 있다 | AI가 계산하거나 지어냈다 | `숫자 대조표에 없는 숫자를 모두 찾아 지우거나 "Excel 계산 필요"로 바꿔라.` |
| 5 | 리포트가 "한도를 감액한다"처럼 실행형이다 | 승인 표기를 놓쳤다 | `한도 변경·선적 보류·K-SURE 통지는 '권고(사람 승인 전)'로 고치고 조치마다 승인 주체를 적어라.` |
| 6 | "통지가 늦으면 15/1000 위약금"이라고 썼다 | 약관 한정 조항을 일반화했다 | 그 문장을 지우고 통지 기한은 '결제기일부터 1개월 이내'로만 |
| 7 | 레드팀이 지적을 억지로 만들어 낸다 · 아무 지적도 없다 | 같은 서비스에서 돌렸거나 입력 표를 빠뜨렸다 | 다른 서비스에서 [입력 표]까지 넣어 다시. 지적이 없으면 '지적 없음'이 정상 |
| 8 | 표를 워드로 옮기니 칸이 어긋난다 | 마크다운 표가 글자로 붙었다 | `같은 표를 탭으로 구분된 텍스트로 다시` → 워드 **삽입** → **표** → **텍스트를 표로 변환** |
| 9 | 이슈 초안이 원인을 단정한다 | 4요소보다 추측이 앞섰다 | 원인 후보 줄 끝에 '(확인 전)'을 붙이고, 재현 절차를 번호 목록으로 |
| 10 | 대조표 6번 칸을 채울 수 없다 | 16:45 전이다 | 강사 화면 공개 뒤 채웁니다. 그 전에는 1–5번만 |
