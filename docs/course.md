### 교수목표 — 계획서 원문 {#goals}

> 1. 글로벌 신용조사(K-SURE,D&B) 및 재무 데이터와 비정형 금융 뉴스를 생성형 AI와 머신러닝(LightGBM,Prophet) 알고리즘으로 결합하여,해외 바이어의 대금 연체 가능성 및 부도 위험을 선제적으로 예측하는 능력 배양
> 2. 바이어별 리스크 등급에 따른 맞춤형 여신(외상) 한도 산정 기법을 체득하고,위험 스코어 초과 시 실시간 알림 및 대금 결제 촉구 메일 발송까지 자율 제어하는 AI 에이전트 구축 역량 확보
> 3. 노코딩 툴과 Streamlit 웹 빌더를 활용해 자사 맞춤형 채권 모니터링 상황판을 직접 시제품으로 패키징하고,미수금 감소율 및 업무 시간 단축 등 경제적 효과(ROI/KPI)를 정량적으로 산출한 최종 도입 기획서 완성

!!! note "실습에서는 이렇게 지킵니다"
    알림·메일 '자율 제어'는 **AI가 초안을 만들고 사람이 승인**하는 방식으로 실습합니다. 메일은 모두 DRY RUN(실제 발송 없음)입니다.
    노코드 도구(Orange)에 LightGBM·Prophet 위젯이 없는 단계는 같은 계열 도구로 대신하고, 원형 알고리즘은 🟣 Challenge(Colab)와 강사 시연으로 봅니다(3일차).

### 설계 주안점 — 계획서 원문 {#design}

> - 프로그래밍 코딩 언어 학습을 지양하고, GPT의 데이터 분석 기능, 노코드 시각화 도구 등 마우스 클릭과 자연어 중심의 실습 환경 설계
> - 강사가 제공하는 정형화된 이론 예제를 넘어, 교육생이 직접 담당하는 수출 품목, 결제 방식(L/C, T/T), 바이어 이력 데이터를 실습에 직접 투입하는 과업 중심 구조로 설계

그래서 모든 실습 Step은 **클릭과 자연어로 끝까지 갈 수 있게**(🟢 Basic) 만들고, 같은 Step을 **내 회사 데이터로 다시 하는 길**(🔵 Standard)을 함께 둡니다 — [3트랙](#tracks).

### 파이프라인 6단계 — 어제의 결과가 오늘의 입력 {#pipeline}

```text
① 원시 데이터 확보 및 탐색적 데이터 분석(EDA)          → d1_end_eda   (변수 정의서 · EDA 차트)
② 정형·비정형 융합 특성 공학(Feature Engineering)       → d2_end_features.csv
③ 머신러닝 모델링 및 평가지표 검증                       → d3_end_scored.csv (연체 확률 · S/A/B/C 등급)
④ 예측 기반 의사결정 최적화 및 시뮬레이션                 → d4_end_limits.xlsx (여신 한도 · 시나리오 손실 · 경보)
⑤ 엔드투엔드(End-to-End) 솔루션 패키징 및 배포            → RAG 챗봇 + 통합 대시보드(앱 URL)
⑥ [최종 산출물] AI 기반 무역 금융 리스크 관리 통합 파이프라인 솔루션 킷 → 팀 저장소 v1.0
```

6일 내내 **같은 가상 회사, 같은 파이프라인**입니다. 어제 실습을 다 못 끝냈거나 결석했어도, 매일 **08:30**에 강사 정답본(`d{N}_start.*`)이 공개되어 그 파일로 바로 합류합니다. 파일 이름과 열은 [데이터 → 파일 체인](data.md#chain)에 있습니다.

## 3. 운영 규칙 {#rules}

1. **사람이 최종 결정한다.** 한도 변경 · 선적 보류 · K-SURE 통지 · 바이어 발송은 AI가 초안을 만들고 사람이 승인합니다. 메일은 모두 DRY RUN입니다.
2. **기본은 가상(합성) 데이터.** 회사 실데이터는 익명화한 뒤 내 PC와 회사가 허용한 도구에서만 씁니다. 무료 소비자 AI · 공개 저장소 · 공개 앱에는 올리지 않습니다 → [데이터 위생 5원칙](setup.md#hygiene) · [저장소·앱 규칙](setup.md#repo-hygiene).
3. **근거를 보인다.** AI가 준 문장은 원문에서 찾고, 숫자는 공식·코드로 다시 계산합니다. 검증 전까지는 가설입니다.
4. **모델 이름 대신 '기본 모델 / 추론 모델'.** AI 서비스의 모델 이름과 메뉴는 자주 바뀝니다.
5. **새 일 = 새 채팅.** 대화가 길어지면 AI가 앞의 지시를 놓칩니다.
6. **막히면** 노트북 뚜껑에 빨강 스티커(다 끝나면 초록) → [FAQ](faq.md) → 손들기. 강사도 모르는 실무 질문은 **파킹랏**(벽 전지·Slido)에 적으면 다음 날 1차 자료로 답하고, 답은 매일 18:00 FAQ에 더합니다.
7. **회사 보안 규정이 이 사이트의 안내보다 우선합니다.**

```text
 └─ kit_template/ → brainini/tradefin-kit-template  (팀 킷 템플릿)
       └─ 5일차 8교시: Use this template → 팀 저장소 tradefin-kit-T{조} → 6일차 15:50 v1.0 릴리스
```

- 저장소 이름 · 파일 이름 · 커밋 메시지에 **실명 · 회사명 · 고객사명을 쓰지 않습니다**(예: `tradefin-my-T2-07`).
- 개인 도입 기획서 · ROI 시트 · 사후 진단은 **저장소가 아니라 비공개 폼**으로 냅니다.
- 계정은 [사전 준비 → 언제 가입하나](setup.md#account-timeline)에 날짜별로 정리했습니다.

### Streamlit Community Cloud {#streamlit}

1. [share.streamlit.io](https://share.streamlit.io) → **Continue with GitHub**로 로그인합니다.
2. **Create app** → Repository `{내 아이디}/tradefin-ai-2026` · Branch `main` · Main file `app/streamlit_app.py` · App URL `traderisk-t{조}-{번호}`.
3. **Advanced settings**에서 Python 버전(강사 안내)과 **Secrets**(아래 키 카드 내용)를 넣고 **Deploy**를 누릅니다.
4. 저장소에 커밋하면 1–2분 뒤 자동으로 다시 배포됩니다.

- 12시간 동안 아무도 접속하지 않으면 앱이 잠듭니다. 화면의 깨우기 버튼을 누르면 1–2분 뒤 돌아옵니다(수업일 아침에는 강사가 미리 깨웁니다).
- 비공개 앱은 계정당 1개뿐이라 수업 앱은 **공개 앱 + 합성 데이터**로 만듭니다.
- 앱이 막히면 강사 앱 URL로 진행합니다(그 밖의 백업 경로는 당일 안내).

### LiteLLM 공용 키 카드 {#llm-key}

- 5일차 09:00에 **개인 가상 키**가 적힌 QR 카드를 나눠 드립니다. 가입은 필요 없습니다.
- 하루 예산과 분당 호출 수가 정해진 교육용 키이고, **10/22에 만료**됩니다. 한도에 걸리면 1분 기다리거나 강사에게 예비 키를 요청합니다.
- 모델은 별칭으로만 부릅니다: `fast-default`(기본) · `fast-backup`(예비). 실제 모델은 강사가 관리합니다.
- 키를 넣는 곳은 **Streamlit Secrets 칸, Dify 모델 설정, n8n 자격증명**뿐입니다. 대화창 · 채팅방 · 저장소 · 스크린숏에는 넣지 않습니다.
- 키가 노출되었으면 바로 강사에게 알립니다 — 키를 지우고 예비 키로 바꿉니다(비난하지 않습니다).

Streamlit **Secrets** 칸에는 과정 저장소의 [`app/.streamlit/secrets.toml.example`](https://github.com/brainini/tradefin-ai-2026/blob/main/app/.streamlit/secrets.toml.example) 내용을 통째로 붙여 넣고, `<…>` 자리만 키 카드의 주소 · 키로 바꿉니다. 키를 비워 두면 앱은 모의 모드(템플릿 초안)로 돕니다. 그중 AI 연결 부분은 이런 모양입니다:

```toml
[llm]
base_url = "<키 카드에 적힌 주소>"
api_key = "<내 가상 키>"
default_model = "fast-default"
fallback_models = ["fast-backup"]
```
